# 원격 합방 스튜디오 — 설계 문서

- 작성일: 2026-10-27
- 상태: 승인됨 (2026-10-27)
- 실행계획: `docs/superpowers/plans/2026-10-27-remote-collab-studio.md`
- 작성 방식: 비개발자 1인이 Claude Code로 개발 (개발팀 없음)

---

## 1. 의도와 이유

지금 엑셀방송은 멤버들이 한 스튜디오에 모여서 진행한다. 이 방식에는 스튜디오 비용이 들고, 멀리 사는 멤버를 섭외하기 어렵다는 한계가 있다.

이 프로젝트는 **멤버들이 각자 집에서 브라우저로 접속해, 한 화면에 모여 방송하는 "원격 합방 스튜디오"**를 만든다. 합쳐진 화면은 방장이 평소 쓰는 송출 프로그램(OBS 등)을 통해 어느 방송 플랫폼으로든 내보낸다.

- **1순위 사용자**: 이미 함께하기로 한 특정 엑셀방송 팀. 이 팀이 실제 방송에 쓸 수 있으면 첫 번째 성공이다.
- **확장 대상**: 엑셀방송이 아닌 일반 크리에이터 합방(게임, 토크, 콜라보 등).

따라서 핵심은 **범용 합방 엔진**으로 만들고, 엑셀방송은 그 위에 얹는 **"모드"**로 둔다.

## 2. 목표 / 비목표 / 실패 조건

### 목표 (v1)
> v1의 성공 기준: 엑셀 팀이 실제 인원으로 비공개 리허설 방송을 끝까지 문제없이 마치는 것.

1. 멤버가 링크 하나로 브라우저에서 입장하고, 서로 지연 없이 보고 들으며 대화할 수 있다.
2. 방장이 콘솔에서 멤버 음소거·강조, 레이아웃 전환, 테스트 후원 발생을 할 수 있다.
3. **엑셀 모드**: 후원이 들어오면 순위표가 자동 갱신되고, 순위에 따라 멤버 화면의 크기와 위치가 바뀐다. 후원 알림은 화면과 멤버 귀에 동시에 전달된다.
4. **일반 합방 모드**: 그리드 / 스포트라이트 레이아웃과 후원 알림.
5. 합쳐진 방송 화면을 **브라우저 소스 주소 하나**로 제공해, OBS·PRISM 등을 통해 SOOP, 치지직, 유튜브, 트위치 등 어디로든 송출할 수 있다.

### 비목표 (v1에서 하지 않음)
- BGM 싱크와 동시 댄스 연출
- 실제 투네이션 후원 연동 (v1은 테스트 후원만. 단, 나중에 교체하기 쉬운 구조로 만든다)
- 정산 자동화
- 멤버별 개인 채널 동시 송출, 여러 채널 후원 합산
- 시청자용 자체 시청 페이지
- 모바일 앱 (PC 브라우저 우선)

### 실패 조건 (기능이 돌아가도 실패로 보는 경우)
- 실제 방송에서 쓰기에 소리가 불안정함 (에코, 하울링, 끊김, 멤버 간 음량 차이)
- 방장이 방송 중에 조작하기 어려움
- 엑셀 기능이 엔진에 강하게 묶여서, 일반 합방에 쓰려면 다시 만들어야 함

## 3. 제약 조건

- **개발자**: 비개발자 1인이 Claude Code로 개발한다. 직접 만드는 코드는 최소화하고, 어려운 영역(실시간 영상·음성 전송, 에코 제거)은 검증된 관리형 서비스에 맡긴다.
- **운영**: 서버를 직접 관리하지 않는다. 클릭 몇 번으로 배포되는 호스팅을 쓴다.
- **검증 방식**: 단계마다 비개발자가 브라우저에서 직접 눌러 보고 확인할 수 있는 결과물이 있어야 한다.
- **인원**: 구조상 인원 제한은 두지 않는다. **v1은 동시 출연 12명까지를 품질 보장 목표**로 잡고, 초과 인원은 "대기석"(화면에는 안 보이고 음성만, 또는 목록만)으로 처리한다. 실제 테스트 후 조정한다.
- **플랫폼**: 특정 방송 플랫폼에 의존하지 않는다.

## 4. 결정된 사항

### 사용자가 결정한 것
- 엑셀 팀 실전 투입을 우선하고, 일반 합방까지 쓸 수 있게 만든다.
- 개발팀 없이 혼자 진행한다. 설명은 비개발자 눈높이에 맞춘다.
- 후원은 테스트 후원으로 시작한다.
- v1은 대화·리액션·순위 경쟁 중심으로 한다 (댄스와 BGM 싱크 제외).
- 인원 제한과 플랫폼 제한은 두지 않는다.
- **v1은 리허설용이다.** 실제 후원이 오가는 정식 방송은 실 후원 연동(v2)이 붙은 뒤에 한다. 따라서 v1에서는 실 후원을 손으로 입력하는 기능을 만들지 않는다.
- **방장도 카메라에 나오는 출연자다.**
- **순위는 회차를 넘어 이어진다.**

### 작성자(Claude)가 정한 것 — 사용자가 바꿀 수 있음
- **실시간 영상·음성**: LiveKit Cloud (WebRTC SFU). 에코 제거, 노이즈 억제, 화질 자동 조절(simulcast)을 기본 제공한다.
- **웹 앱**: Next.js (React) + TypeScript. LiveKit 공식 React 컴포넌트를 쓸 수 있다.
- **배포**: Vercel.
- **데이터 저장과 실시간 공유**: 방, 멤버, 회차, 시즌, 후원 내역은 Supabase(데이터베이스)에 저장한다. 방송 중 화면 간 즉시 반영(순위 갱신, 레이아웃 변경, 후원 알림)은 LiveKit 데이터 채널 또는 Supabase 실시간 기능으로 전달하되, 기준 데이터는 항상 DB에 둔다.
- **송출 방식**: 방송 화면 페이지(`/room/{id}/output`)를 OBS 브라우저 소스로 넣는다. 서버 측 합성(LiveKit Egress → RTMP)은 v2 옵션으로 남긴다.
  - 이유: 비용이 낮고, 방장이 기존 OBS 장면·오버레이와 섞어 쓸 수 있으며, 플랫폼 제약이 없다.
- **멤버 리턴 피드**: 멤버는 송출 화면이 아니라 LiveKit 룸에서 직접 서로를 보고 듣는다(송출 지연과 되먹임 방지).

### 검토 후 작성자(Claude)가 정한 것 — 사용자가 바꿀 수 있음
- **출연석과 대기석**: 엑셀 모드에서는 기본적으로 순위 상위 N명이 출연석에 앉는다(N은 방장이 설정하고, 기본값은 12). 방장이 콘솔에서 수동으로 덮어쓸 수 있다. 대기석 멤버의 음성은 기본적으로 방송에 나가고, 방장이 대기석 전체를 음소거할 수 있다. 대기석 멤버의 영상은 방송 화면에서 구독하지 않는다(대역폭 절약).
- **레이아웃 결정 주체**: 모드 플러그인이 "누가 어디에 얼마나 크게"를 계산하고, 엔진은 그 결과를 그대로 그린다. 방장의 수동 지정은 모드 계산보다 우선한다.
- **접근 제어**: 로그인 없이 비밀 링크를 쓴다. 멤버 링크, 방장 콘솔 링크, 방송 화면 링크를 각각 다른 비밀 토큰으로 분리한다. 서버가 LiveKit 입장 토큰을 발급하고, 내보낸 멤버는 재입장을 차단한다. 방장은 링크를 재발급할 수 있다(유출 대비).
- **방장 = 출연자 + 조작자**: 방장은 멤버와 똑같이 입장 페이지로 출연하고, 방장 콘솔은 별도 창으로 연다. 콘솔은 **휴대폰이나 보조 모니터에서도 큰 버튼으로 조작**할 수 있게 만든다. 방송 중 자주 쓰는 동작(음소거, 강조, 레이아웃 전환, 후원 알림 넘기기)은 한 번에 누를 수 있어야 한다. 보조 운영자에게 줄 수 있는 "운영자 링크"(콘솔과 같은 권한, 출연 없음)도 제공한다.
- **방장 PC 소리 처리**: 방송 화면 페이지가 방장 목소리를 포함한 모든 출연자 소리를 믹스한다. 방장은 OBS에 마이크를 따로 추가하지 않는다(소리가 두 번 들어가는 문제 방지). 설정 안내 화면에서 이 점을 명시한다. 방장이 OBS 마이크를 꼭 써야 하는 경우를 위해 "방송 화면에서 방장 소리 빼기" 옵션을 둔다.
- **회차와 시즌**: 방(=하나의 쇼)은 여러 회차에 걸쳐 재사용된다. 순위는 **시즌** 단위로 누적되고, 방장이 시즌을 마감하고 새로 시작할 수 있다. 순위표에는 "시즌 누적"과 "이번 회차"를 함께 보여줄 수 있다. 이를 위해 **처음부터 데이터베이스(Supabase)를 쓴다.**
- **비용 상한**: 멤버 송출 화질은 기본 720p, 방송 화면은 타일 크기에 맞는 화질만 받도록 제한한다. 4단계 이후 실제 사용량으로 월 예상 비용을 계산해 공유하고, 사용자 확인 후 리허설로 넘어간다.

## 5. 구성 요소

### 5.1 화면(페이지) 4종

| 페이지 | 사용자 | 역할 |
|---|---|---|
| 방 만들기 | 방장 | 방 이름과 모드(엑셀 / 일반) 선택, 멤버 초대 링크 생성 |
| 멤버 입장 | 멤버 | 닉네임 입력 → 카메라·마이크·회선 점검 → 헤드셋 안내 → 입장. 입장 후 다른 멤버 화면과 후원 알림이 보임 |
| 방장 콘솔 | 방장 | 멤버 목록, 음소거·강조·내보내기, 레이아웃 전환, 테스트 후원 버튼, 순위표 수동 수정, 출연/대기석 전환 |
| 방송 화면 | OBS | 합쳐진 레이아웃 + 순위표 + 후원 알림만 깔끔하게 표시 (조작 UI 없음, 1920×1080 기준) |

### 5.2 모드 구조
- **공통 엔진**: 입장, 미디어 연결, 음소거·강조, 레이아웃 렌더링, 후원 이벤트 처리 흐름.
- **모드 = 플러그인**: 각 모드는 (1) 후원 이벤트를 받아 상태를 바꾸는 규칙과 (2) 상태를 레이아웃으로 바꾸는 규칙만 정의한다.
  - 엑셀 모드: 멤버별 누적 후원액 → 순위 → 직급 표시, 순위별 타일 크기·위치.
  - 일반 합방 모드: 그리드 / 스포트라이트, 후원받은 멤버를 잠깐 강조.
- 새로운 모드(예: 팀 대결)를 추가할 때 엔진 코드는 수정하지 않는 것을 목표로 한다.

### 5.3 후원 이벤트
- 표준 형식(예시): `{ 후원자명, 금액, 대상 멤버, 메시지, 시각, 출처 }`
- v1 출처: 방장 콘솔의 테스트 후원 버튼.
- 나중에 투네이션 실시간 연동으로 교체할 때는 **출처 부분만 바꾸면** 되도록 한다.
- 후원 알림: 방송 화면(시청자용)과 멤버 화면(리액션용)에 동시에 표시하고, 알림음을 재생한다.

### 5.4 오디오 원칙
- 헤드셋 착용을 입장 단계에서 강하게 안내한다. 스피커 사용이 감지되면 경고한다(가능한 범위에서).
- 브라우저 / LiveKit의 에코 제거, 노이즈 억제, 자동 음량 조절을 켠다.
- 방송 화면 페이지는 OBS에서 모든 멤버 소리를 믹스해 출력한다. 멤버 화면은 자기 소리를 제외하고 듣는다(LiveKit 기본 동작).
- 방장 콘솔에서 멤버별 볼륨을 조절할 수 있다(방송 화면 믹스 기준).

### 5.5 상태 보존
- 방송 중 새로고침하거나 재접속해도 순위표와 후원 내역이 사라지지 않아야 한다.
- 순위는 시즌 단위로 회차를 넘어 누적된다. 같은 멤버는 회차가 바뀌어도 같은 사람으로 인식되어야 한다(멤버 링크 또는 멤버 등록 정보로 식별).
- 방송이 끝난 뒤에도 회차별·시즌별 후원 내역을 파일(CSV)로 내려받을 수 있다(정산 자동화 이전의 최소 기능).
- v1의 후원은 테스트 후원이므로, 테스트 데이터와 이후 실 후원 데이터가 섞이지 않게 출처를 구분해 저장하고, 테스트 데이터는 한 번에 지울 수 있게 한다.

## 6. 진행 단계 (실행계획의 큰 틀)

각 단계는 비개발자가 브라우저에서 확인할 수 있는 결과로 끝난다.

1. **준비**: LiveKit Cloud와 Vercel 계정 만들기, 프로젝트 생성. (확인: 빈 페이지가 인터넷 주소로 열림)
2. **2인 화상 연결**: 링크로 두 사람이 입장해 서로 보고 듣기. (확인: 노트북과 휴대폰 등 두 기기로 대화)
3. **방장 콘솔 기본**: 멤버 목록, 음소거, 강조, 내보내기.
4. **방송 화면 + OBS 연결**: 그리드 레이아웃을 OBS 브라우저 소스로 띄우고 테스트 송출.
5. **테스트 후원과 알림**: 후원 버튼 → 방송 화면과 멤버 화면에 알림 표시.
6. **엑셀 모드**: 순위표, 순위별 레이아웃 자동 재배치, 시즌·회차 누적, CSV 내보내기.
7. **입장 점검과 오디오 다듬기**: 장비 점검, 헤드셋 안내, 멤버별 볼륨, 방장 OBS 설정 안내.
8. **실전 리허설 (v1 완료 기준)**: 엑셀 팀과 실제 인원으로 비공개 테스트 방송 → 문제 목록화 → 수정.
9. **v2 — 정식 방송의 전제 조건**: 실 후원 연동(투네이션 우선). 그 밖의 후보: 정산, 멀티 채널 송출, BGM 싱크.

## 7. 빌더에게 맡기는 것
- 화면 디자인 세부 사항(색상, 폰트, 애니메이션). 단, 방송 화면은 방송용으로 가독성이 높아야 한다.
- 엑셀 모드의 구체적인 레이아웃 공식(순위별 타일 크기 비율 등). 첫 안을 만든 뒤 엑셀 팀 피드백으로 조정한다.
- 폴더 구조, 라이브러리 세부 선택, 테스트 방식.

## 8. 리스크와 확인할 것
- **LiveKit Cloud 비용**: 인원 × 방송 시간에 비례한다. 리허설 전에 예상 월 비용을 계산해 공유한다.
- **OBS 브라우저 소스의 성능**: 12명 영상을 브라우저 소스 하나에서 디코딩하면 방장 PC에 부하가 걸린다. 4단계에서 미리 측정한다.
- **멤버 환경 다양성**: 회선, 카메라, 브라우저가 제각각이다. 7단계 장비 점검으로 대응한다.
- **플랫폼 정책**: 외부 후원 표시와 오버레이 관련 각 플랫폼 정책은 실 후원 연동(v2) 전에 확인한다.
- **정식 방송 시점은 v2에 달려 있다**: 엑셀 팀의 주 후원 수단이 별풍선·치즈라면, 투네이션 연동만으로는 순위표가 완성되지 않는다. v1 리허설 중에 엑셀 팀의 후원 수단 비중을 확인해 v2 범위를 정한다.
